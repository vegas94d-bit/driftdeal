## 1. Краткий обзор

`driftdeal` — это Git-репозиторий, который на текущий момент находится в состоянии заготовки. В нём нет исходного кода, конфигурационных файлов, системы сборки, зависимостей и тестов. Единственный файл — `README.md` с заголовком `# driftdeal`.

Назначение проекта по содержимому репозитория не задокументировано. Название может указывать на тему дрифта, но это остаётся предположением, а не подтверждённым требованием.

**Текущий статус:** проект без кода (пустой каркас).

## 4. Тип проекта

Проект относится к категории **«проект без кода»**:

- отсутствуют `package.json`, `requirements.txt`, `composer.json`, `Cargo.toml`, `go.mod`, `pom.xml`, `build.gradle` и другие манифесты;
- нет каталога `src` и исполняемых файлов;
- нет Docker-конфигурации, CI/CD-файлов и скриптов автоматизации;
- нет документации, кроме минимального `README.md`.

Определить язык программирования, фреймворк, архитектуру и целевые платформы по текущему состоянию невозможно.

## 6. Правила разработки

Правила кодирования, тестирования и контрибуции в репозитории пока не установлены. До их появления действуют общие принципы:

1. **Минимальность изменений.** Не добавлять инфраструктуру, зависимости и абстракции без необходимости.
2. **Ясность структуры.** При появлении кода разделить исходники, ресурсы, тесты и документацию по отдельным каталогам.
3. **Актуальность документации.** Любое изменение стека, команд запуска или архитектуры должно отражаться в `README.md` и `KODA.md`.
4. **Единый стиль.** Следовать стилю уже существующего кода; пока код отсутствует, стиль считается незаданным.
5. **Безопасность.** Не коммитить секреты, ключи, локальные настройки и сгенерированные артефакты; при необходимости добавить `.gitignore`.
6. **Проверяемость.** Новый функционал должен запускаться по документированной команде и, при наличии тестовой инфраструктуры, покрываться тестами.

Язык документации — русский. Язык кода и комментариев не зафиксирован и должен определяться после появления первых исходников.

## 7. Как использовать репозиторий

Сейчас репозиторий можно использовать только как точку старта:

1. Клонировать репозиторий.
2. Определить цель проекта и технологический стек.
3. Добавить исходники, манифест зависимостей и инструкции запуска.
4. Обновить `README.md` и `KODA.md` в соответствии с фактической структурой.

Запускать, собирать или тестировать пока нечего.
