# KODA.md

> Инструкционный контекст для будущих взаимодействий с репозиторием `driftdeal`.

## 1. Краткий обзор

`driftdeal` — браузерная 2D-игра про дрифт с видом сверху. Реализована в одном самодостаточном файле `index.html` на чистых HTML, CSS и JavaScript. Вся графика рисуется через Canvas, внешних картинок, звуков, библиотек и сборки нет.

**Текущий статус:** рабочий прототип, запускается двойным кликом по `index.html`.

## 2. Структура каталога

```text
driftdeal/
├── index.html   # вся игра: разметка HUD, стили, физика, рендер, звука нет
├── README.md    # описание, запуск, управление, правила геймплея
└── KODA.md      # этот файл
```

## 3. Ключевые файлы

| Файл | Назначение |
| --- | --- |
| `index.html` | Единственный исходник игры. Внутри: Canvas-рендер, физика дрифта, трасса, частицы, следы, HUD, ввод, игровой цикл. |
| `README.md` | Пользовательская документация: запуск, управление, геймплей. |

## 4. Тип проекта

Проект без сборки и зависимостей: статическая веб-страница.

- нет `package.json` и других манифестов;
- нет тестовой инфраструктуры;
- нет CI/CD и Docker;
- внешние ресурсы не используются.

## 5. Сборка, запуск и тестирование

- **Запуск:** открыть `index.html` в современном браузере (Chrome, Edge, Firefox, Safari).
- **Сборка:** не требуется.
- **Тесты:** автоматических тестов нет. Проверка выполняется вручную в браузере.

При добавлении тестов или сборки зафиксировать команды в этом разделе и в `README.md`.

## 6. Правила разработки

1. **Один файл.** Пока проект остаётся прототипом, весь код держать в `index.html`, без внешних зависимостей.
2. **Canvas-only графика.** Не добавлять изображения, шрифты, аудиофайлы и библиотеки без явной необходимости.
3. **Производительность.** Игровой цикл — только через `requestAnimationFrame`; физика с фиксированным шагом; тяжёлые статические слои кэшировать в offscreen-canvas; ограничивать число частиц.
4. **Читаемость.** Секции кода разделены комментариями (утилиты, трасса, текстуры, физика, частицы, рендер, ввод). Стиль — `const`/`let`, стрелочные функции, без точек с запятой после блоков.
5. **Документация.** Изменения управления, геймплея или запуска отражать в `README.md` и `KODA.md`.
6. **Безопасность.** Не добавлять секреты и внешние запросы; игра должна работать офлайн с `file://`.

## 7. Архитектура `index.html`

- **Мир:** `WORLD_W × WORLD_H`, трасса — замкнутая центральная линия из 900 точек, построенная по модулированному эллипсу. Ширина асфальта, поребриков и зоны вылета задаётся в объекте `TRACK`.
- **Кэш мира:** трасса, поребрики, стены и декорации один раз рисуются в offscreen-canvas `world`; следы от покрышек добавляются в него же.
- **Физика:** раздельные продольная и поперечная скорости в системе координат машины, инерция, плавное рулевое. Боковая сила покрышек — модель Magic Formula Pacejka (`tireForce`, коэффициенты `PHYS.TIRE_DRY/HE/OFF`): линейна при малом угле скольжения, насыщается на пике сцепления — за пиком наступает занос. Ручник роняет пик задней оси с последующим восстановлением, полный газ в скольжении срезает цепкость (friction circle). Рыскание — кинематическая цель по рулю + самовыравнивание по заносу + стабилизатор. Фиксированный шаг `1/120` с накоплением времени.
- **Геймплей:** очки копятся в `game.bank` при дрифте на трассе, множитель `x2/x3/x5` по времени непрерывного заноса, перенос в `game.total` после паузы, сгорание при вылете или ударе о стену. Рекорд — `localStorage` ключ `driftdeal.best`.
- **Рендер:** камера следует за машиной с упреждением по скорости, лёгкий зум от скорости и тряска; HUD — DOM-панели и отдельный Canvas-спидометр.
- **Эффекты:** дым и пыль — частицы; следы — линии в offscreen-слое мира.

## 9. Рекомендации для будущих взаимодействий

- Перед изменением физики проверять поведение численно и в браузере: разгон, поворот, ручник, контрруль, удержание заноса.
- Не увеличивать число частиц и следов без необходимости: они влияют на FPS.
- После правок `index.html` проверять синтаксис и запускать страницу в браузере.
- Поддерживать `README.md` и `KODA.md` в актуальном состоянии.
